4Proposed — one control, one decision surface

The revised model — four rules, both apps

  1. One decision control, ever. A single split pill in a single slot — the header never shows Approve and Send Feedback side by side. The left segment is the state's primary: Done (annotate) / Approve (review) when there is nothing to send; Send Feedback · n when there is. The flip is state-driven and mirrored by the visible count; the left segment always does exactly what its label says, in one click.
  2. The caret carries the alternate decision(s) and the note — never the header. The caret opens a small action menu; choosing a "…with a note" item expands the composer in place, inside the same popover. Every menu action is explicitly labeled for its whole outcome. In each state the menu offers the opposite decision, so nothing is unreachable: request-changes lives under Done/Approve, approve lives under Send Feedback.
  3. Close is an escape hatch, not a peer. A quiet ghost X at the cluster's left; warns only when content would be lost; tooltip states the flavor-specific consequence (annotate-last: "Dismiss without telling the agent").
  4. ⌘↩ = the visible primary. Outside the popover it triggers the left segment; inside the composer it triggers the composer's labeled action. The keyboard and the header can never disagree, because there is exactly one primary.
P1 — Nothing to send: one green control

"That's fine & done" is one click. The caret's menu holds everything else: the note, and the opposite decision — overall change-request feedback with zero annotations (which is how the in-flight pill's zero-state note path survives, without a Send button in the header).
